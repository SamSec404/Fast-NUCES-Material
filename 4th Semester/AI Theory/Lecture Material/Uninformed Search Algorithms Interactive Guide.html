🔍 Uninformed Search Algorithms

Interactive Step-by-Step Guide to Classical AI Search Strategies

📚 What are Uninformed Search Algorithms?

Uninformed search algorithms (also called blind search) are strategies that explore a search space without any domain-specific knowledge about the goal location. They only know:

  • How to generate successors of a state
  • How to recognize the goal state
  • The cost of actions (for some algorithms)
🎯 Key Point: These algorithms differ in the order in which they expand nodes, leading to different performance characteristics.

Space Complexity

🌊 Breadth-First Search (BFS)

Core Concept

BFS explores the search tree level by level, expanding all nodes at depth d before moving to depth d+1. It uses a FIFO (First-In-First-Out) queue.

🎯 Strategy: "Explore broadly before going deep"

How It Works

  1. Start with the initial node in the queue
  2. Remove the front node from the queue
  3. If it's the goal, return the solution
  4. Otherwise, add all its children to the back of the queue
  5. Repeat until goal is found or queue is empty

Pseudocode

function BFS(start, goal): frontier ← Queue() frontier.enqueue(start) explored ← ∅ parent[start] ← null while frontier is not empty: node ← frontier.dequeue() if node == goal: return reconstruct_path(parent, node) explored.add(node) for each child in successors(node): if child not in explored and child not in frontier: parent[child] ← node frontier.enqueue(child) return failure

Step-by-Step Execution

Step 0: Initialize with node A
Step Queue (Front → Back) Node Expanded Children Added Explored Set
0 [A] - - { }
1 [B, C] A B, C {A}
2 [C, D, E] B D, E {A, B}
3 [D, E, F] C F {A, B, C}
4 [E, F] D - {A, B, C, D}
5 [F, G] E G {A, B, C, D, E}
6 [G] F - {A, B, C, D, E, F}
7 [ ] G ✅ - {A, B, C, D, E, F, G}
✅ Solution Found: A → B → E → G (Cost: 3)

Search Tree Construction

[A] / \ [B] [C] / \ \ [D] [E] [F] \ [G] ← Goal found at depth 3

Complexity Analysis

⏱️ Time Complexity

O(bd)

Expands all nodes up to depth d

💾 Space Complexity

O(bd)

Must store all nodes at current level

✅ Complete

Yes

If branching factor is finite

🎯 Optimal

Yes

For uniform step costs

⚠️ Main Drawback: High memory consumption! BFS stores all nodes at the current level, which can be exponentially large.

🏔️ Depth-First Search (DFS)

Core Concept

DFS explores the search tree by going as deep as possible along each branch before backtracking. It uses a LIFO (Last-In-First-Out) stack.

🎯 Strategy: "Explore deeply before exploring broadly"

How It Works

  1. Start with the initial node on the stack
  2. Pop the top node from the stack
  3. If it's the goal, return the solution
  4. Otherwise, push all its children onto the stack
  5. Repeat until goal is found or stack is empty

Pseudocode

function DFS(start, goal): frontier ← Stack() frontier.push(start) explored ← ∅ parent[start] ← null while frontier is not empty: node ← frontier.pop() if node in explored: continue if node == goal: return reconstruct_path(parent, node) explored.add(node) // Push in reverse order so leftmost is processed first for each child in reverse(successors(node)): if child not in explored: parent[child] ← node frontier.push(child) return failure

Step-by-Step Execution

Step 0: Initialize with node A
Step Stack (Top → Bottom) Node Expanded Children Pushed Explored Set
0 [A] - - { }
1 [B, C] A B, C {A}
2 [D, E, C] B D, E {A, B}
3 [E, C] D - {A, B, D}
4 [G, C] E G {A, B, D, E}
5 [C] G ✅ - {A, B, D, E, G}
✅ Solution Found: A → B → E → G (Cost: 3)
📝 Note: Node C was never explored! DFS found the goal before needing to explore that branch.

Search Tree Construction

[A] / [B] / \ [D] [E] \ [G] ← Goal found (Branch C-F was never explored)

Complexity Analysis

⏱️ Time Complexity

O(bm)

May explore entire tree to depth m

💾 Space Complexity

O(b·m)

Only stores path + siblings

✅ Complete

No

Can get stuck in infinite branches

🎯 Optimal

No

Returns first solution found

⚠️ Main Drawback: Not optimal and can get trapped in deep branches. However, it's very memory-efficient!

📏 Depth-Limited Search (DLS)

Core Concept

DLS is DFS with a predetermined depth limit L. It prevents infinite descent but may miss solutions deeper than L.

🎯 Strategy: "Explore deeply, but not too deeply"

How It Works

  1. Perform DFS with a depth counter
  2. When depth reaches limit L, stop expanding that branch
  3. Return "cutoff" if limit reached, "failure" if no solution exists
  4. If goal found within limit, return solution

Pseudocode

function DLS(node, goal, limit): if node == goal: return success if limit == 0: return cutoff cutoff_occurred ← false for each child in successors(node): result ← DLS(child, goal, limit - 1) if result == cutoff: cutoff_occurred ← true else if result == success: return success if cutoff_occurred: return cutoff else: return failure

Example: DLS with Limit = 2

⚠️ Problem: Our goal G is at depth 3, so with limit L=2, we cannot reach it!

Nodes Explored (Limit = 2)

Depth Nodes at This Depth Status
0 A ✅ Explored
1 B, C ✅ Explored
2 D, E, F ✅ Explored (limit reached)
3 G ❌ Not explored (beyond limit)
[A] / \ [B] [C] / \ \ [D] [E] [F] Limit reached! G is beyond depth 2.

Example: DLS with Limit = 3

✅ Success: With limit L=3, we can reach G!
[A] / \ [B] [C] / \ \ [D] [E] [F] \ [G] ← Found within limit!

Complexity Analysis

⏱️ Time Complexity

O(bL)

Explores all nodes up to depth L

💾 Space Complexity

O(b·L)

Linear in depth limit

✅ Complete

Only if L ≥ d

Must set limit deep enough

🎯 Optimal

No

Returns first solution found

💡 Key Insight: DLS solves DFS's infinite-depth problem but introduces a new problem: choosing the right limit!

🔄 Iterative Deepening Search (IDS)

Core Concept

IDS repeatedly runs DLS with increasing depth limits (0, 1, 2, 3, ...). It combines the space efficiency of DFS with the optimality of BFS!

🎯 Strategy: "Try shallow first, then gradually go deeper"

How It Works

  1. Start with depth limit L = 0
  2. Run DLS with current limit
  3. If solution found, return it
  4. If cutoff occurred, increment L and repeat
  5. If failure (no cutoff), no solution exists

Pseudocode

function IDS(start, goal): for depth = 0 to ∞: result ← DLS(start, goal, depth) if result == success: return solution if result == failure: return failure return failure

Step-by-Step Execution

Iteration 1: Limit = 0

[A] Result: Cutoff (goal not found)

Iteration 2: Limit = 1

[A] / \ [B] [C] Result: Cutoff (goal not found)

Iteration 3: Limit = 2

[A] / \ [B] [C] / \ \ [D] [E] [F] Result: Cutoff (goal not found)

Iteration 4: Limit = 3

[A] / \ [B] [C] / \ \ [D] [E] [F] \ [G] ← Goal found! Result: Success!
✅ Solution Found: A → B → E → G (Cost: 3)

Why Re-expansion Isn't Too Costly

You might think: "We're re-expanding nodes multiple times! Isn't that wasteful?"

💡 Surprising Fact: Most nodes are at the deepest level! Re-expanding upper levels adds only a small overhead.

Mathematical proof: For b=2, d=3:
• Nodes at depth 3: 8
• Nodes at depth 2: 4
• Nodes at depth 1: 2
• Nodes at depth 0: 1

Total re-expansions ≈ (b/(b-1)) × nodes at depth d ≈ 2 × 8 = 16
This is only 2× the work of BFS, but uses O(bd) space instead of O(bd)!

Complexity Analysis

⏱️ Time Complexity

O(bd)

Same as BFS (with small constant factor)

💾 Space Complexity

O(b·d)

Linear! Much better than BFS

✅ Complete

Yes

Will eventually try all depths

🎯 Optimal

Yes

For uniform step costs

🏆 Best Uninformed Strategy: IDS is often the preferred uninformed search when the search space is large and the solution depth is unknown!

💰 Uniform-Cost Search (UCS)

Core Concept

UCS expands the node with the lowest path cost g(n) from the start. It uses a priority queue ordered by cumulative path cost.

🎯 Strategy: "Always expand the cheapest path first"

How It Works

  1. Start with initial node in priority queue (cost = 0)
  2. Remove node with lowest path cost
  3. If it's the goal, return the solution
  4. Otherwise, add children with updated path costs
  5. Repeat until goal is found

Pseudocode

function UCS(start, goal): frontier ← PriorityQueue() frontier.insert(start, priority=0) explored ← ∅ best_g[start] ← 0 parent[start] ← null while frontier is not empty: node ← frontier.remove_min() if node == goal: return reconstruct_path(parent, node) explored.add(node) for each child in successors(node): new_cost ← best_g[node] + cost(node, child) if child not in explored: if child not in frontier or new_cost < best_g[child]: best_g[child] ← new_cost parent[child] ← node frontier.insert_or_update(child, priority=new_cost) return failure

Step-by-Step Execution (Unit Costs)

📝 Note: Since all edges in our example have cost = 1, UCS behaves identically to BFS!
Step Priority Queue (node:cost) Expanded Path Cost
0 {A:0} - -
1 {B:1, C:1} A 0
2 {C:1, D:2, E:2} B 1
3 {D:2, E:2, F:2} C 1
4 {E:2, F:2} D 2
5 {F:2, G:3} E 2
6 {G:3} F 2
7 { } G ✅ 3
✅ Optimal Solution: A → B → E → G (Total Cost: 3)

Search Tree with Costs

[A:0] / \ [B:1] [C:1] / \ \ [D:2] [E:2] [F:2] \ [G:3] ← Optimal path (lowest cost)

Example with Non-Uniform Costs

Let's see where UCS really shines! Consider this modified graph:

A / \ 1/ \5 / \ B C | | 1| 1| | | G G
💡 Key Insight: BFS would find path A→C→G (2 steps), but UCS finds A→B→G (cost 2) instead of A→C→G (cost 6). UCS is optimal even when the shortest path has more steps!

Complexity Analysis

⏱️ Time Complexity

O(bC*/ε)

C* = optimal cost, ε = min edge cost

💾 Space Complexity

O(bC*/ε)

Must store all frontier nodes

✅ Complete

Yes

If all costs are positive

🎯 Optimal

Yes

Always finds lowest-cost solution

🏆 When to Use UCS: Essential when edge costs vary! It's the foundation for A* search (informed search).

Decision Guide: Which Algorithm to Use?

Use BFS when:

  • Solution is likely shallow
  • All step costs are equal
  • You have enough memory
  • You need the optimal solution

Use DFS when:

  • Memory is severely limited
  • Solutions are deep in the tree
  • You don't need the optimal solution
  • The tree has a known maximum depth

Use IDS when:

  • You don't know the solution depth
  • Memory is limited
  • You need the optimal solution (uniform costs)
  • This is often the best default choice!

Use UCS when:

  • Edge costs vary
  • You need the lowest-cost solution
  • You have enough memory
  • Preparing to use A* (informed search)

Key Takeaways

🎯 Optimality

BFS, IDS, and UCS guarantee optimal solutions (with appropriate cost functions)

💾 Memory

DFS and IDS are memory-efficient; BFS and UCS can be memory-intensive

⏱️ Time

All uninformed algorithms have exponential time complexity in the worst case

🏆 Winner

IDS combines the best of both worlds: optimal + memory-efficient

⚠️ Important Limitation: All uninformed search algorithms have exponential complexity. For large search spaces, informed search (like A*) using heuristics is necessary!
